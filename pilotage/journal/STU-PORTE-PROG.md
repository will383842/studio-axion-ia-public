# STU-PORTE-PROG : programmation de l'usine par la porte v2 (appel 4)
Fait : POST /api/usine/programmations (src/app/api/usine/programmations/route.ts) et service src/services/porte-programmations.ts. Même forme que l'appel 1 (commandes) : `garderPorte` (jeton, contrat 2, champs permis seulement, 16 Ko), clé d'idempotence `cle` → entrée `prog-<cle>`.
Règles : une programmation crée une entrée d'origine « usine », à l'état « a_valider », avec la date par défaut ; elle ne passe jamais à « valide » (geste tracé du fondateur) ; rien ne part chez le diffuseur (le service n'importe aucun fournisseur ni le port d'envoi ; aucun envoi planifié n'est écrit). Champ optionnel `entreeId` : l'usine propose une date pour une entrée existante ; si cette entrée a une origine « vous » (ou aucune : entrée d'avant), la date du fondateur est conservée (`ecritureDatePermise`) ; si elle est d'origine usine et encore à relire (propose / a_valider), la date par défaut est révisée sans toucher au statut. Tout champ de statut ou de validation (statut, valideeLe, valideePar, origine…) → 400 `champ_invalide`. Rejeu : 200 `deja`, aucun doublon, jamais de retour en arrière d'une entrée déjà validée.
Dépendance : `validerEntree` (CAL-21, geste du fondateur dans actions/ajouter.ts) existe sur master mais n'est PAS appelée ici ; aucune interface injectée n'a donc été nécessaire.
Tests : test rouge d'abord (route absente) ; tests/porte-v2 : 45 verts (11 nouveaux). eslint propre sur les 3 fichiers ; tsc : aucune erreur sur les fichiers touchés (146 erreurs déjà présentes sur master, inchangées, dans d'autres fichiers).
Mutations temporaires (toutes restaurées) : statut « a_valider » non posé → 2 rouges (critère 1) ; appel réseau ajouté → 1 rouge (critère 1, aucun envoi) ; garde d'origine retirée → 2 rouges (critère 2) ; champs de statut permis → 1 rouge (critère 3) ; contrôle de rejeu retiré → 2 rouges (critère 3) ; refus de jeton ignoré → 4 rouges (critère 3).
Reste / non prouvé : forme exacte du corps de l'appel 4 côté usine (reprise de l'appel 1 + `entreeId`, à confirmer) ; code HTTP 201/200 à confirmer ; aucun quota par jour appliqué (hors fiche). Aucun prix, aucun prénom ni nom.
