# L7-06-4-3 : refus côté serveur de l'outil « buffer »
Fait : `envoyerParOutilAction` (src/services/a-publier-zernio.ts) refuse un `outil: "buffer"` venu du client avec le code `OUTIL_REFUSE`, juste après la vérification de session et avant toute autre étape : rien lu en base, rien écrit, aucun appel au diffuseur, aucun journal d'envoi. Zernio explicite et absence d'outil : inchangés. Le routage par configuration (outilDeEnvoi) n'est pas touché.
Tests : tests/publication/l7-06-4-3-refus-buffer.test.ts (rouge d'abord ; mutations temporaires restaurées : refus retiré → test « buffer » rouge ; refus de tout ce qui n'est pas zernio → test « absence d'outil » rouge ; refus de tout → tests « zernio » et « absence » rouges).
Accord écrit du parcours viral (14/11, canal de coordination) : adaptation de tests/zernio/e2e-04-service.test.ts uniquement, pour les appels `{ outil: "buffer" }` (6 appels, 6 tests) : ils attendent désormais `OUTIL_REFUSE`. Conséquences inévitables dans ces mêmes tests : les attentes qui supposaient un envoi Buffer réussi changent (compte de mutations Buffer 0 au lieu de 1 ; « changer de date » : l'envoi Zernio suivant passe car Buffer n'a rien envoyé ; le test « déjà envoyé par Buffer : Zernio refuse » devient un test de refus du seul appel Buffer, la phrase « Déjà envoyée par Buffer » n'étant plus atteignable par cette entrée). La couverture de l'anti-doublon Buffer→Zernio par une autre entrée Buffer reste à décider par le parcours viral.
