# L7-06-4-3 : le serveur route Buffer, le client ne le choisit plus
Fait : `envoyerParOutilAction` (src/services/a-publier-zernio.ts) : `outil` absent ou « zernio » = chemin Zernio comme avant ; « buffer » n'est accepté QUE si `outilDeEnvoi(reseau)` (configuration lue côté serveur) place ce réseau chez Buffer, auquel cas le chemin Buffer habituel s'exécute ; tout autre cas (buffer alors que la configuration dit Zernio ou illisible, casse différente, espaces, chaîne vide, null, valeur inconnue) : refus `OUTIL_REFUSE` avant tout effet (rien écrit, aucun appel au diffuseur, aucun journal d'envoi). Le code Buffer de `essayer` sert donc toujours (pas de code mort) ; commentaire de tête corrigé.
Écran « À publier » : `LignesAPublier.tsx` (l.62 et l.361) envoie `complement.outil`, qui vaut « buffer » pour un compte routé chez Buffer : le serveur le confirme par la configuration, l'envoi passe, sans toucher à l'écran. Prouvé par tests/zernio/e2e-04 (routage `instagram: "buffer"`, appels `{ outil: "buffer" }`).
Tests : tests/publication/l7-06-4-3-refus-buffer.test.ts (compte routé Buffer → 1 publication, 1 envoi Buffer ; compte routé Zernio ou configuration illisible → OUTIL_REFUSE sans aucun appel ; Buffer/ buffer/BUFFER/inconnu/""/null/0 → OUTIL_REFUSE). Mutations restaurées : contrôle de configuration retiré → 2 rouges ; validation de valeur retirée → 8 rouges ; refus de tout « buffer » → 1 rouge.
tests/zernio/e2e-04-service.test.ts : REMIS tel qu'à l'origine (identique à master) : le banc route Instagram chez Buffer, donc les appels `{ outil: "buffer" }` d'origine sont acceptés et toutes les assertions d'origine (phrases « Déjà envoyée par … », mutations, `ok: false`/`posts 0` après changement de date, post Buffer réel relu) sont restaurées, aucune retirée.
